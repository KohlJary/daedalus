# Edict 0012: The Daedalus TUI
Status: accepted
Depends on: Edicts 0007, 0008, 0009 (the state it shows); Edict 0011 for the Sources screen and
source proposals (the TUI ships without them and shows Sources once any exist)

## Intent
Make Daedalus usable by someone who wasn't there when it was built.

Everything Daedalus keeps exists today: the gameplan, edicts, dissents, workstreams, the board,
doctor and session notes. But it's only reachable by people who already know the vocabulary and
the commands. The TUI is the way in. It shows that state on one screen next to a live Claude Code
session, explains each concept where it appears, and teaches the CLI behind every view, so a
newcomer can leave the TUI and keep going.

This supersedes the Dec 2025 "CLI/TUI Removal" decision in `.daedalus/decisions.md`. That decision
removed an earlier dashboard because "Claude Code is the interface". The reason here is different:
legibility for people who weren't in the room. Nothing from the old TUI is carried forward.

Drafted by Daedalus at Kohl's request in conversation on 2026-10-14. The design is in
`docs/design/tui/`: Ophanic diagrams, README, glossary, coverage.

## Constraints
- **The diagrams are the reference layout.** The `.oph` files in `docs/design/tui/` fix the
  structure: panels, screens, variants, what each detail view shows, and the key bindings. Their
  sample content is illustrative. A PR that deviates updates the diagram in the same PR and says why.
- **Textual, as an optional extra.** It installs with `pip install daedalus[tui]` and runs with
  `daedalus tui`. A plain install doesn't pull Textual in.
- **One source of truth.** The TUI calls the same library functions as the CLI and never parses CLI
  output. One file watcher over `.daedalus/` and `docs/edicts/` feeds every panel. There are no
  polling loops per panel.
- **Writes in v1 are exactly these:**
  - apply or drop a pending proposal (gameplan or reflection);
  - edit a config setting;
  - follow or unfollow a board thread;
  - run a fix that `doctor` names, after a confirmation modal;
  - once edict 0010 has merged, the owner's own reflection data:
    - edit, mark stable, forget or delete a model entry. Forget follows
      `reflection.forget`, and every change goes to the model's history the
      same way the CLI does it. Aspirations stay Daedalus's to write;
    - digest now;
    - export the experiment log to a path the owner picks.
  Each of these calls the same library function as its `daedalus reflect` command, and forget
  and delete confirm in a modal first.
- **Judgment stays where it lives.** Merging a PR, accepting an edict and posting to the board
  happen in their own channels. The TUI shows them and offers to hand them to Claude. It has no
  merge, accept or post key.
- **The Claude pane is a real Claude Code session; how it's hosted is an implementation choice.**
  - **What it must do:** run Claude Code in the project's working directory, render it in the pane,
    and pass keys through.
  - **What the hosting mechanism should give:** the session survives the TUI exiting and can be
    reached from a plain terminal.
  - **Where it lives:** the mechanism sits behind a small backend interface. Candidates are tmux,
    another multiplexer, a detach tool, or a session process Daedalus runs itself. Past trouble with
    tmux in the cass-vessel TUI is a reason to compare them, not to assume tmux.
  - **The fallback:** a plain PTY child that ends with the TUI. It's always available, and the pane
    says so when it's in use.
  - **Recording the choice:** the PR that picks a backend records why in `.daedalus/decisions.md`.
- **Focus model.** While the Claude pane has focus, every key goes to Claude except one escape
  chord: `ctrl+]`, unless Claude Code turns out to use it, in which case another single chord. The
  key bar always shows which mode is active. There are no priority bindings that could steal keys
  from the terminal.
- **Send to Claude pastes, never submits.** There is always one human keystroke between a selection
  and Claude acting on it.
- **Legible to a newcomer:**
  - every panel has an Explain card (`?`) with three parts: what it is, where it lives, the CLI that
    shows it;
  - the card text ships as package data, drawn from `docs/design/tui/glossary.md`;
  - empty states say what will appear and how to start it;
  - labels say what a thing is, not its codename;
  - nothing assumes the owner is Kohl.
- **Config is editable and secrets are invisible.** Every setting `daedalus config` knows can be
  edited at a chosen layer (user or project). That requires a config schema with a description,
  type and default for every key; the description is the key's Explain card. Credentials are kept
  in the system keyring and are never displayed or written to a config file.
- **Plugins contribute through entry points** in the group `daedalus.tui`. A plugin may add:
  - a NeedsYou kind (tag, detail renderer, actions);
  - Explain cards;
  - a screen reached from a menu.
  The shell layout is not pluggable.
- **Code shape.** There is one widget per `◆component` in the diagrams, with its CSS beside it, and
  no module over 800 lines. The stylesheet uses theme tokens only.
- **PRs in NeedsYou** come from local branches ahead of `main` by default. `tui.prs: gh` uses the
  GitHub CLI when it is installed and authenticated.

## Acceptance criteria
- `daedalus tui` opens the shell from `shell.oph`. At 100 columns or more it shows the desktop
  layout; below that, the narrow tabbed layout. A project with no gameplan, edicts or sessions
  shows the first-run Welcome.
- NeedsYou lists PRs, proposed edicts, open dissents, board threads with unread posts and pending
  proposals. Each kind has the detail and actions in `needs-you.oph`.
- The Gameplan (plan and workstreams), Health, Story, Edicts, Board and Config screens match their
  diagrams. Sources matches `sources.oph` whenever a source from edict 0011 is configured.
- The Claude pane can start a new session and attach an existing one. Tests show that:
  - with the persistent backend, a session survives quitting and relaunching the TUI;
  - when that backend is unavailable, the plain-PTY fallback runs and the pane says the session
    won't outlive the TUI;
  - while the pane has focus, `j`, `k`, `q` and `?` reach the PTY;
  - the escape chord returns focus to the dashboard.
- Swapping the session backend changes no code outside the backend module, shown by running the
  pane tests against at least two backends (the persistent one and the fallback).
- Send to Claude puts the prompt in Claude's input without a trailing newline; a test checks this.
- `?` shows an Explain card on every panel. Every concept carded in `coverage.md` has its text.
- Config edits write to the chosen layer and round-trip through `daedalus config`. Reading a
  secret's value from the TUI is impossible; a test checks this.
- A plugin in a separate test package adds a NeedsYou kind and an Explain card through the entry
  point.
- Once edict 0010 has merged, a Reflection screen shows what's due, reports, the user model, the
  self model and the A/B experiment, as in `docs/design/tui/reflection.oph`. Model-entry edits made
  from the TUI produce the same history records as the CLI, which a test checks. Stances can only
  be applied one at a time, as in the CLI.
- Each screen has a Textual pilot smoke test, and none of the tests use the network.
- The PR updates `docs/design/tui/coverage.md` to what actually shipped and adds a History row.

## Non-goals
- No merging, accepting or posting from the TUI.
- No views in v1 for the Ariadne bus and plans, Momus beyond the PR badge, Theseus reports or the
  Mind Palace. They are listed as gaps in `coverage.md` for a later edict.
- No `@wide` layout, and no web UI.
- Ophanic as a Daedalus feature is a separate question, tracked in the gameplan notes for this
  phase.
- No carry-over of code from the removed Dec 2025 TUI.

  Why: the user model is the owner's data about themselves, and they should be able to correct
